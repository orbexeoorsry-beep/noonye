## بصمة البناء الذي اختُبر

بُنيت الملفات محليًا بعد الاختبارات؛ قائمة SHA256 لكل ملفات `dist` في [build-sha256.txt](evidence/build-sha256.txt). بصمة ملف القائمة:

```text
ccd726d58cfaa0c39c665e947ca761917a73e579cbdbd828f1873fd5de6c34ce
```

أُثبت تطابق استجابة HTML على `http://127.0.0.1:4173/` مع `dist/index.html` byte-for-byte، والتفاصيل في [preview-identity.json](evidence/preview-identity.json). الأصول لها قائمة منفصلة للتحقق؛ لا نزعم أن فحص HTML وحده يثبت كل أصل بعيد. أعادت المعاينة HTTP 200، ونجحت e2e على هذه الخدمة المحلية بعد البناء. الرابط الخارجي يحيل إلى المنفذ نفسه، وليس بيئة إنتاج ثابتة أو استضافة إصدار دائمة.

البصمة أعلاه تخص **بناء المعاينة فقط**، لا إنتاج Hostinger. لا نملك بصمة إنتاج مرتبطة بـSHA. يلزم لاحقًا قراءة حزمة النشر النشطة/manifest من الاستضافة وربطها بسجل بناء ناجح ومصدر كامل، مع حفظ runtime/start وبصمات الأصول والخادم. لا يُحسم ذلك من commit metadata أو لقطة نجاح قديمة.
