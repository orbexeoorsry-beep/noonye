## خريطة البنية

- `src/App.tsx` و`src/pages/`: التنقل، المكتبة، رفع الكتاب، وصفحة التقدم.
- `src/features/book-viewer/`: تحميل مصدر المستند، عرض الصفحات، احتواء العرض والتكبير والتنقل إلى الاستشهاد.
- `src/features/local-documents/services/pdf-upload.ts` و`src/services/pdfService.ts`: فحص الملف وتحليله، مع رفض التالف والفارغ والمزيف والمحمي والمتجاوز للحجم.
- `src/services/local-document-store/`: IndexedDB لحفظ الملف وبياناته وموضع القراءة؛ إخفاقات صريحة بدل إظهار نجاح وهمي أو كتاب بديل.
- `src/features/pdf-study/`: استخراج النص وترتيبه وبناء مراجعة محلية مقتبسة مرتبطة بالصفحات. ليست خدمة توليد AI ولا OCR.
- `src/i18n/`: العربية والإنجليزية واتجاه RTL/LTR.
- `src/config/featureFlags.ts` و`src/services/aiGateway.ts` و`server.ts`: تعطيل AI في العميل والخادم. تبقى واجهة `/api/assistant/explain` وترد 503، وhealth يعلن التعطيل.
- `scripts/copy-pdf-assets.mjs`: نسخ أصول PDF.js المطابقة للإصدار محليًا قبل البناء/التطوير.
- `tests/`: اختبارات وظائف وتخزين Chromium فعلي واختبارات واجهة ومعاينة.

## ما يتغير في نسخة المراجعة

رفع PDF حقيقي وحفظه محليًا وأخطاء واضحة دون تعويضه بمادة أخرى؛ مراجعة محلية من نص الصفحات مع روابط استشهاد؛ تصحيح احتواء صفحات الهاتف والتنقل؛ ترجمة شاشة المراجعة العربية/الإنجليزية؛ إخفاء مؤشرات تقدم تجريبية غير موثقة؛ وتعطيل AI صراحةً في الطرفين. تتضمن النسخة التغييرات السابقة كلها، وليست مجرد إصلاح CSS محدود. قائمة فرق الملفات الأولية محفوظة في `evidence/original-worktree-diff.txt`؛ الملفات الجديدة تظهر في Git نفسه.

## الاختبارات وإعادة التشغيل

```sh
npm test
npm run lint
npm run build
# في طرفية منفصلة، بعد البناء:
npm run preview -- --host 0.0.0.0 --port 4173
# ثم:
PREVIEW_URL=http://127.0.0.1:4173 E2E_ARTIFACT_DIR=/tmp/noon-review-e2e npm run test:e2e
sha256sum -c docs/release/evidence/build-sha256.txt
```

بيئة التحقق: Node v24.19.0، npm 11.17.0، Chromium `/usr/bin/chromium`. التثبيت الأصلي يعتمد `bun.lock`، ولا يوجد `package-lock.json`؛ لا تستخدم `npm ci`. يلزم تثبيت الاعتماديات بحسب القفل في بيئة نظيفة قبل قبول قابلية إعادة الإنتاج النهائية؛ ذلك لم يُختبر هنا.

`npm test` يشغّل ستة مداخل مباشرة، ويستدعي `pdf-viewer.test.ts` اختبارات التخزين `local-documents.test.ts` التي تبني وتشغّل `local-documents.browser.ts` داخل Chromium حقيقي، ويستورد `progress-page.test.ts`. لذلك هذه الاختبارات **مشمولة بصورة غير مباشرة**، وليست فجوة كما قد يوحي تعداد scripts وحده.

اختبارات e2e تستخدم ملفات مصطنعة داخل سياقات متصفح جديدة؛ لا تُختبر على الإنتاج. الهاتف محاكاة لمس 390×844، لا جهاز حقيقي. السيناريوهات تشمل العربية، تبديل AR/EN، ملفات ممسوحة ومختلطة، الرفع غير الصحيح، ثبات الحفظ، الاستشهادات 2–3، وعدم إرسال مستند/بيانات طالب إلى AI. توجد طلبات GET لخطوط Google؛ لا يصح وصف التطبيق بأنه بلا أي اتصال خارجي.

## حدود القبول والمخاطر

- نجاح بناء Vite لا يثبت جاهزية حزمة Hostinger: script الحالي يبني العميل فقط، ولا يولّد `dist/server.js` كما يفعل المصدر البعيد `5db0ce9`. يلزم حسم عقد runtime/start وموضع static واختبار الحزمة على staging قبل الإصدار. لم نغيّر الخادم المحلي لاستعادة شيفرة AI القديمة.
- تحذير حجم chunk يتجاوز 500KB وتحذير Vite عن `__dirname` موجودان؛ ليسا فشلًا للبناء، لكن الأداء على هاتف حقيقي لم يُقَس.
- لا OCR؛ صفحات الصور تعرض السبب ولا تختلق ملخصًا أو درجات. المراجعة تدريب اقتباسي محلي وليست شرحًا مولدًا موثوقًا.
- تعطيل AI وتغيير عرض التقدم تغييرات سلوكية يجب عرضها على جينو، لا تمريرها تحت عنوان إصلاح المعاينة فقط.
- الاسم الوارد في التكليف `noon.roubwx.com` يختلف عن السجل المفتوح `noon.roubex.com`. لا نعتمد هدف نشر قبل تأكيده.

## خطة الرجوع — قبل أي إصدار وبعد موافقته

الآن لا تغيير إنتاجي يحتاج إلى رجوع. لا تستخدم reset/clean/stash أو إعادة كتابة الملفات المحلية. الأرشيف المحفوظ في `/workspace/noonye-release-safety/worktree-before-release.tar.gz` والنسخة الأقدم `/workspace/noonye-review-baseline/before-review.tar.gz` للاستعادة إلى **مجلد جديد** وفحصه أولًا، لا لاستخراجه فوق مساحة العمل.

قبل نشر مستقبلي: حفظ الحزمة النشطة نفسها وبصمتها وID نشرها وإعداد start/runtime غير السري، وإثبات تطابقها. لا يكفي اختيار `a44fd759` من عنوان سجل. بعد موافقة محددة: إذا فشلت health أو تحميل الأصول أو smoke tests، الرجوع إلى الحزمة المثبتة السابقة بآلية الاستضافة المعتمدة، ثم إعادة health والأصول وإعلان النتيجة. لا حذف/ترحيل قواعد بيانات، ولا تدوير أسرار، ولا تغيير حسابات. لا تحذف بيانات IndexedDB للمستخدم؛ قد تتطلب بعض حالات الملف المفقود إعادة رفعه بموافقته.
