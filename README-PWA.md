# نون — تثبيت شاشة الهاتف فقط

هذه إضافة PWA محلية فوق الشجرة المعتمدة `484359a44f8f3e7cb241a51e29bccf18ccbe99d5`. لم تُضف أغلفة Android/iOS أو بوابة عمر أو دفع أو مفاتيح أو رفعًا سحابيًا. أعلام الميزات والإصلاح المعتمد محفوظة.

## البناء والمعاينة

```sh
npm run build
PORT=4187 node scripts/pwa-preview.mjs dist
```

يشغّل الأمر الثاني خادمًا ثابتًا على `0.0.0.0` يخدم `dist` فقط، دون backend أو fallback للمسارات المجهولة. لا تشغّل `server.ts` للمعاينة المحدودة. يدعم Service Worker سياق HTTPS أو localhost الآمن. استُخدمت التبعيات المحلية الموجودة عبر symlink؛ لم تُثبّت خدمة مدفوعة أو تبعيات جديدة.

التثبيت من قائمة المتصفح: Chrome يدعم تثبيت التطبيق/إضافته للشاشة الرئيسية؛ في Safari على iPhone تُستخدم المشاركة ثم «إضافة إلى الشاشة الرئيسية». قد تختلف التسمية والتوافر حسب الجهاز. لا نافذة ترويج أو زر إضافي يزحم الواجهة. الأيقونات تعيد استخدام شكل شعار نون الحالي: مربع slate مستدير وحرف نون أبيض ونقطة indigo، دون صور خارجية؛ تشمل maskable وبيانات Apple.

## ما الذي يُخزّن دون اتصال؟

يولّد `scripts/generate-pwa-sw.mjs` قائمة سماح محددة من ملفات البناء: HTML الجذر، JS/CSS المرتبطة به ومراجع الحزم الثابتة، عامل PDF.js المحلي، manifest والأيقونات المحددة. لا يجول مجلد public عشوائيًا، ويرفض المسارات خارج هذه الفئات. عامل PDF.js هو كود ثابت، وليس ملف الطالب.

تُثبت القائمة دفعة واحدة في cache مستقل باسم `noon-shell-<بصمة المحتوى>`. تُجلب الملفات دون cookies وببصمات SHA-256 للتحقق من تطابقها مع البناء، دون قبول redirects. إذا فشل أي ملف يُحذف cache الإصدار الجديد ويفشل التثبيت؛ لا يُحذف الإصدار العامل. لا توجد كتابة runtime إلى cache.

تُخدم الملفات الثابتة فقط عند تطابق الأصل والمسار تمامًا ودون query. fallback التنقل محصور بالجذر `/`. مسارات API والحساب/الملف الشخصي والإعدادات والطلاب وPDF والمسارات غير المعروفة، والطلبات غير GET أو ذات Authorization/Range، لا تُخدم من كاش العامل. أجزاء العنوان `#fragment` لا تُرسل في HTTP، لذلك واجهات التطبيق المبنية على hash تشترك في shell الثابت نفسه؛ ليست حماية وصول أو عزلًا لبيانات الواجهة.

**ملفات PDF والملاحظات والتقدم والإعدادات المحلية ليست في Cache API، لكنها قد تبقى متاحة دون اتصال عبر IndexedDB/localStorage الموجودين أصلًا.** لا يغيّر هذا العمل قواعد حفظها أو يحذفها. لا ينبغي الادعاء بأن بيانات الطالب كلها غير قابلة للوصول دون اتصال. ملفات الطالب لا تُرفع إلى خادم.

أصبح عامل PDF.js أصلًا محليًا ذا بصمة. موارد CMAP والخطوط القياسية لبعض ملفات PDF ما زالت خارجية كما في خط الأساس؛ لذلك لا نضمن عمل كل PDF دون إنترنت. قد يستخدم الخط العام بديل النظام عند غياب الشبكة. التخزين المحلي يخضع لمساحة الجهاز وسياسة مسح بيانات المتصفح؛ ليس نسخة احتياطية سحابية.

## تحديث الكاش والرجوع

تتغير البصمة عند تغير محتوى أي أصل مسموح. لا `skipWaiting` ولا إعادة تحميل تلقائية أثناء قراءة PDF. يبقى الإصدار الجديد منتظرًا حتى إغلاق كل نوافذ التطبيق الخاضعة للعامل القديم ثم فتح التطبيق مجددًا؛ مجرد refresh مع بقاء نافذة قديمة قد لا يفعله. عند التفعيل الناجح تُحذف caches القديمة ذات البادئة `noon-shell-` فقط، ولا تُحذف IndexedDB/localStorage أو caches أخرى.

الرجوع هو تقديم **حزمة البناء القديمة كاملة** بما فيها `sw.js` والأصول المطابقة. ينتظر العامل القديم كأي تحديث ثم يتفعّل عند انتهاء جلسات الإصدار الحالي. لا يكفي استبدال SW وحده أو حذف ملفات الواجهة القديمة أثناء القراءة. لم يُنفذ تحديث أو رجوع في الإنتاج.

## إعادة الاختبارات

```sh
npm run lint
npm test
node tests/pwa-browser.test.mjs
```

الاختبار الأخير يتطلب Chromium في `/usr/bin/chromium` والتبعيات المحلية المتاحة، ويستخدم ملفات تعريف اختبار مؤقتة وPDF اصطناعيًا فقط. يحفظ أدلته في `PWA_EVIDENCE` أو افتراضيًا `/workspace/noonye-pwa-evidence-20261022`. يشغّل خادم اختبار loopback مؤقتًا؛ لا يلمس خادم المعاينة أو الإنتاج. يفحص manifest وقابلية التثبيت عبر CDP، واجهات 390×844 بالعربية RTL والإنجليزية LTR، محتوى Cache API، PDF محليًا، تحديث A→B وفشل التنزيل والرجوع B→A. لا يمثل محاكاة Chromium اختبار Safari أو جهاز هاتف فعلي، ولا تثبيتًا فعليًا على شاشة هاتف. لا يوجد Lighthouse مثبت في بيئة المراجعة؛ استُخدمت واجهات تدقيق Chromium المتاحة بدل اختلاق درجة تدقيق.

## لاحقًا: Capacitor، دون تنفيذ الآن

في مهمة مستقلة بعد الموافقة: إضافة Capacitor ونسخ build المحلي إلى أغلفة Android/iOS؛ فصل تسجيل SW عند التشغيل الأصلي؛ مراجعة file picker والصلاحيات وخصوصية المتاجر؛ واختبار تخزين PDF على أجهزة حقيقية. **لا نفترض انتقال IndexedDB تلقائيًا من PWA إلى WebView**: يلزم مسار تصدير/استيراد محلي واضح وموافقة المستخدم دون رفع سحابي. بعد ذلك فقط تُجهز هوية التطبيق والتوقيع واختبارات المتاجر ونماذج الخصوصية. لم تُنشأ أغلفة أو شهادات أو طلبات نشر أو اشتراكات في هذا العمل.
